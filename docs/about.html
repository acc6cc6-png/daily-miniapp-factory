System Notes

AI 自动造物系统

这不是单纯的热点站点，而是一条“采集信号 -> 过滤需求 -> 生成方案 -> 发布到 GitHub Pages”的自动流水线。

今日方案 查看今天最值得做的小程序方案 市场信号 查看用来支撑方案判断的研究台 原始监控 排查抓取源和原始标题质量 系统说明 了解采集、评分、去重和部署方式

当前发布方式

GitHub Actions 定时运行 Python 脚本，生成 `docs/data/latest/digest.json` 后由 GitHub Pages 直接发布。

当前默认在北京时间 07:00 和 12:30 自动刷新：07:00 使用“昨收后到 07:00”的窗口，12:30 使用“07:00 到 12:30”的窗口，也支持在 GitHub Actions 中手动触发。

Architecture

系统结构

站点前端是纯静态页面：首页读取 `digest.json` 里的 `miniappFactory` 字段，研究台继续读取同一份 `digest.json` 的研究结果，监控页读取 `raw/latest.json`。

后端脚本先抓取多类信号源，再对热点做去重、过滤、商业价值打分、方向匹配和历史去重，最后生成今天最值得做的小程序方案。

Collection

怎么更高效地采集信息

  1. 优先抓三类高信号源：产品榜单与开发者社区、科技媒体、中文热点与用户讨论。
  2. 先去掉体育、明星、纯娱乐八卦，再按商业关键词、动作关键词和跨源重复度加权。
  3. 只保留最近 48 小时内仍有价值的信号，避免旧热点污染今日方案。

Quality

怎么提高生成效率和质量

  1. 用预设蓝图库约束输出，确保每个方案都能落回“需求、功能、页面、交互、实现、推广”这条主链。
  2. 至少要求两个来源组同时命中，降低“单一热点误导”的风险。
  3. 读取历史快照，对最近重复方向降权，尽量保证每天都有新主题。
  4. 如果仓库配置了 `OPENAI_API_KEY`，会在规则引擎选题后再用模型做一轮结构化润色。

Publish Flow

发布流程

  1. GitHub Actions 运行 `scripts/daily_digest_v2.py`。
  2. 脚本会同时生成研究结果、原始快照和今日小程序方案，并写入 `docs/data`。
  3. 同一条工作流会把 `docs/` 打包并发布到 GitHub Pages。

Local Run

本地运行与密钥

本地可以直接运行 `py scripts/daily_digest_v2.py`。如果 `.env.local` 或 GitHub Secrets 里配置了 `OPENAI_API_KEY`，系统会尝试生成更完整的自然语言版本；没有密钥也能正常走规则引擎。

公开仓库不要提交真实密钥。Pages 站点只读取静态 JSON，不依赖常驻后端。
